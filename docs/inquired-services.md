# Inquired Services and questionnaire feedback

Updated 20 October 2026.

Clients submit **Send Inquiry** on a package's Contact page. The inquiry and its message to the director are committed together. Contact-page visits and generic chat messages do not grant feedback eligibility.

The client sees **Awaiting director confirmation** in **Inquired Services**. Only the parlor's owning director can select **Confirm Inquiry** in **Service Inquiries**. Confirmation records the director and timestamp. Only a confirmed inquiry or availed service with that confirmation can submit feedback, enforced server-side. Clients cannot unlock feedback by submitting status/confirmation fields. Directors may mark a confirmed service availed or cancel an open inquiry. Clients can use Inquire Again after a service is marked availed.

The feedback form uses the 22 Part II service statements from `Questionnaire4RespondentsNotFinished (1).docx`, grouped as Location (3), Budget (5), Religion (2), Casket (2), Service Delivery (4), Documentation (3), Wake Arrangement (2), and Flowers (1). The source labels the wake-arrangement group ?D. Casket?; the UI adds ?Wake arrangement? for clarity. Statements preserve the supplied wording. Instructions explain the source scale: 5 Strongly Agree, 4 Agree, 3 Neutral, 2 Disagree, 1 Strongly Disagree. All statements use matching numeric radio controls, without preselected answers. Every answer is validated and saved individually; the questionnaire mean is stored to two decimal places as the package review score. The review and all 22 answers commit or roll back together.

Each confirmed experience allows one immutable questionnaire, enforced by a unique review constraint. Resending an active inquiry does not create another review opportunity. After a service is marked availed, the client can send another inquiry about the same package. This creates a separate unconfirmed experience; the director must confirm it before it allows one questionnaire. Cancelled inquiries may also be restarted through Contact. A hidden previous-inquiry reference and transaction locks prevent double-submitted or stale forms from creating duplicate experiences. The director-side Record Repeat Service action has been removed.

General cards have no feedback links. Existing parlor ratings and client comments remain visible and unchanged. Package Details also shows read-only package reviews. ?No reviews yet? appears only when both recorded ratings and package reviews are absent. There is no listed-services count badge. Averages refresh after submission, every 10 seconds on open catalog tabs, and on same-browser cross-tab notification.

For deployment run `php scripts/migrate_confirmed_questionnaire.php`. This creates the inquiry/review tables if needed, adds confirmation fields and per-question answer storage, and changes package review scores to decimals without deleting existing reviews. Fresh installations include the same schema in `sql/setup.sql`. The migration was applied locally. Previously submitted feedback is retained; no existing inquiry is silently auto-confirmed. Two pre-existing scheduled funeral records have no parlor association on their packages, so no provider link or review entitlement was guessed.

Validation includes 59 endpoint scenarios; MySQL temporary-table checks for confirmation, ownership, immutable feedback, repeat-service entitlement, rollback of partial questionnaire answers, fractional averages, and message-delivery rollback; source-document verification of all 22 statements; live-refresh JavaScript checks; and responsive Firefox fixtures. Browser fixtures use isolated records, not real user submissions. Complete authenticated HTTP journeys and physical devices have not been tested.

Recovery copies are under `.codex-review/20261020-confirmed-questionnaire/` and earlier task directories. Coordinate restoration with collaborators; never overwrite later edits or drop tables containing collected responses.
